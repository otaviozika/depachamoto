DESPACHEFULL v3.0.0 — RELATÓRIO DE VALIDAÇÃO
================================================

RECURSO
Presença diária por QR + Dashboard operacional por equipe presente.

REGRAS IMPLEMENTADAS
- Motoboys ativos = presença confirmada no dia.
- Fora da loja = presentes com saída ativa (em rota ou retornando).
- Disponíveis = presentes sem saída ativa.
- Pedidos hoje = pedidos iFood recebidos no sistema no dia.
- Motoboy sem presença não pode registrar saída.
- Admin não pode criar saída manual para motoboy ausente até confirmar presença.
- Admin pode confirmar presença manualmente com motivo obrigatório.
- Presença é persistida por dia no PostgreSQL/Supabase.
- Relatório diário inclui presentes mesmo com zero entregas.
- Histórico anterior recebe presença LEGACY_INFERRED uma única vez a partir das saídas existentes.

QR
- Token assinado com HMAC-SHA256.
- Data operacional validada em America/Sao_Paulo.
- Expiração do token validada no backend.
- QR renovado automaticamente na página do Admin.
- Token sobrevive ao fluxo de login do motoboy no mesmo navegador.
- Um registro por motoboy/data.

BANCO
- courier_attendance criada automaticamente no startup.
- Índices por data e por motoboy.
- UNIQUE(courier_id, attendance_date).
- Nenhum SQL manual necessário.
